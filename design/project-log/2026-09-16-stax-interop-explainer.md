Author: `dev-l1-docs` · Date: 2026-09-16 · Role: developer / technical writer

## What shipped

Deliverable D2 of the L1 Stax-interop work: a polished Stax-interop explainer,
authored as the single-source-of-truth page `docs/stax-interop.md` and wired into
the Starlight docs site. This is a docs-only deliverable; no Go behavior changed.

- **New page:** `docs/stax-interop.md` (route `/mizan/guides/stax-interop/`).
  Covers: what Stax is and why interop matters (Mizan-user oriented); the exact
  Mizan-template to Stax-DTO mapping as a table; rubric to Option B fan-out
  (one `LLMEvaluatorRequestDTO` per criterion, `id::group::criterion` naming) and
  pointwise to a direct single DTO; `systemInstruction` to a `SYSTEM` prompt and
  metric to a `USER` prompt; `output_categories` as `[{name, value:String}]` in
  ascending numeric order; `output_format_type: "Choices"`; `variables`; how to
  run the export (real command and flags including `--model-id`); what a consumer
  does with the artifact (POST each array element to the create-evaluator
  endpoint, no batch endpoint exists); and an honest fidelity/limitations section
  (model_id as a user-supplied deployment binding under N3; the
  `@NotNull`-not-`@NotBlank` nuance and the "fill `--model-id` before POST" rule;
  fail-closed on pairwise/custom_schema/non-text; no overall-score rollup on the
  Stax side; generic interior Likert band names). Includes real-DTO JSON examples
  consistent with the byte-locked golden test.
- **DOC_MAP:** added exactly one entry (`stax-interop.md` to the `guides` tree) in
  `docs-site/scripts/sync-docs.mjs`. The guides sidebar is autogenerated, so the
  page appears in nav with no further wiring. No generated tree was hand-edited.
